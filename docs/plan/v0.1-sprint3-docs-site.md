# v0.1 Sprint 3 Plan: Documentation Site

## Sprint Goal and Scope

Document the `nisar_play` package in a pythonic way and publish the
documentation on GitHub: adopt NumPy-style docstrings, build a MkDocs
(Material theme) site with an mkdocstrings-generated API reference plus
the existing narrative docs, and deploy it to GitHub Pages with a GitHub
Actions workflow.

Supports non-functional requirement **N2** (documentation kept up to
date); no new data-processing functionality.

## Clarified Decisions

- **Docstring convention:** NumPy style, applied to all public modules,
  functions, and the package `__init__` (`sme2.py`, `plots.py`, `cli.py`).
- **Generator:** MkDocs + Material theme + mkdocstrings (python handler),
  configured in `mkdocs.yml`; Markdown-native so existing `docs/*.md`
  pages (design, requirements, roadmap) can be included with minimal
  changes.
- **Hosting:** GitHub Pages, deployed by a GitHub Actions workflow
  (`.github/workflows/docs.yml`) on pushes to `main`; site at
  `https://captainkirk99.github.io/nisar_play/`.
- **Dependencies:** new `docs` optional-dependency group in
  `pyproject.toml` (`mkdocs`, `mkdocs-material`, `mkdocstrings[python]`).

## Major Tasks (dependency order)

1. **Docstring conversion:** reformat docstrings in
   `src/nisar_play/{__init__,sme2,plots,cli}.py` to NumPy style
   (Parameters / Returns / Raises sections); no behavior changes.
2. **Docs dependencies:** add the `docs` extra to `pyproject.toml` and
   install into the venv.
3. **MkDocs configuration:** create `mkdocs.yml` (site name, Material
   theme, mkdocstrings plugin with NumPy docstring style, nav covering
   an index page, API reference, and the existing design/requirements/
   roadmap pages).
4. **Docs pages:** add a docs index (from or alongside `README.md`) and
   an API reference page using mkdocstrings directives (e.g.
   `::: nisar_play.sme2`); wire existing `docs/*.md` into the nav.
5. **Local build verification:** `mkdocs build --strict` succeeds in the
   venv; spot-check the rendered API reference.
6. **GitHub Actions workflow:** `.github/workflows/docs.yml` — on push
   to `main`, install the `docs` extra, run `mkdocs build --strict`, and
   deploy to GitHub Pages (actions/deploy-pages or `mkdocs gh-deploy`).
7. **Repository settings:** enable GitHub Pages for the repo (Actions
   source) — may require the user's manual step in repo settings.
8. **Documentation updates** (see below) and housekeeping (`site/` added
   to `.gitignore`).

## Acceptance Criteria

- All public functions/modules in `src/nisar_play/` have NumPy-style
  docstrings.
- `mkdocs build --strict` passes locally with no warnings treated as
  errors.
- The site includes: index, API reference for `sme2`, `plots`, and `cli`,
  and the design/requirements/roadmap pages.
- The Actions workflow builds and publishes the site to GitHub Pages on
  push to `main` (verified after merge/push by the user).

## Testing Requirements

- `mkdocs build --strict` used as the docs regression check (run locally
  this sprint; also runs in CI via the workflow).
- Existing pytest suite still passes (docstring edits must not change
  behavior).
- No new pytest tests required (no new runtime functionality).

## Environment / Dependency Changes

- `pyproject.toml`: new `docs` optional-dependency group: `mkdocs`,
  `mkdocs-material`, `mkdocstrings[python]`.
- New files: `mkdocs.yml`, docs index/API pages under `docs/`,
  `.github/workflows/docs.yml`.
- `.gitignore`: add `site/` (local MkDocs build output).

## Dependencies and Blockers

- Sprints 1-2 complete (code to document exists).
- GitHub Pages must be enabled in the repository settings (user action;
  workflow-based deployment can request it via
  `permissions: pages: write`).
- Deployment triggers on `main`; work merged from the sprint branch will
  publish once pushed to `main`.

## Documentation Updates

- `README.md`: link to the published documentation site and describe how
  to build docs locally (`mkdocs serve`).
- `docs/design.md`: document the docs toolchain (MkDocs + mkdocstrings,
  NumPy docstrings, Pages deployment).
- This plan and the roadmap kept in sync with any deviations.

## Definition of Done

- All acceptance criteria met; `mkdocs build --strict` and the full
  pytest suite pass locally.
- Workflow file in place; site publishes from `main` (user verifies the
  Pages URL after pushing).
- Documentation updated as listed above.
- Changes committed only with user permission (per project rules).
