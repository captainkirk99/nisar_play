# v0.1 Sprint 4: Add CI — Detailed Plan

## Sprint Goal

Add a GitHub Actions CI workflow so branches are tested before merging into
`main`, running the pytest suite and the strict MkDocs build. Make the test
suite runnable in CI, where the large sample SME2 granule is unavailable, by
introducing a small synthetic SME2-like HDF5 test fixture.

## Scope

**In scope:**
- A CI workflow (`.github/workflows/ci.yml`) triggered on `pull_request`
  targeting `main` and `push` to `main`, using Python 3.12
- CI checks: `pytest` and `mkdocs build --strict`
- A synthetic SME2-like HDF5 fixture (same group/dataset structure as the
  real granule, tiny grid) generated by a pytest fixture, used by
  data-dependent tests when the real file in `data/` is absent
- Documentation of the manual branch-protection setup on `main`

**Out of scope:**
- Linting (ruff or similar) — separate scope decision
- Downloading NISAR data in CI, Git LFS
- Python version matrix
- Changes to the docs deploy workflow (`docs.yml`)

## Background / Constraint

The sample SME2 file
`data/NISAR_L3_PR_SME2_...001.h5` (119 MB) is untracked; only its small
`.iso.xml`/`.rc.yaml` sidecars are in git. All current tests
(`tests/test_read_sme2.py`, `tests/test_plots_sme2.py`) open that file, so a
plain CI checkout would fail every test. The sprint resolves this with a
synthetic fixture rather than skipping tests, so CI still meaningfully
exercises the reader, plotting, and CLI code.

## Tasks (dependency order)

1. **Synthetic SME2 fixture**
   - Add a pytest fixture (e.g. in `tests/conftest.py`) that writes a small
     HDF5 file with the SME2 structure used by the code:
     `/science/LSAR/SME2/grids` containing `soilMoisture`,
     `soilMoistureUncertainty`, `retrievalQualityFlag`, `latitude`,
     `longitude`, `xCoordinates`, `yCoordinates` (tiny grid, e.g. 10×10),
     including fill values and quality-flag bits so masking logic is
     exercised. Use the netCDF4/h5py APIs already available.
   - Provide a session-scoped fixture that resolves to the real sample file
     when present, otherwise the synthetic file, and give the synthetic file
     an SME2-conforming name so filename-based discovery works.
2. **Adapt tests**
   - Point `tests/test_read_sme2.py` and `tests/test_plots_sme2.py` at the
     fixture path instead of hard-coding `data/` discovery.
   - Keep assertions that are specific to the real granule (e.g. known
     lat/lon bounds region) conditional on the real file being present.
3. **CI workflow**
   - Add `.github/workflows/ci.yml`: checkout, setup-python 3.12,
     `pip install -e ".[dev,docs]"`, run `pytest`, run
     `mkdocs build --strict`.
   - Trigger on `pull_request` (branches: `main`) and `push`
     (branches: `main`); minimal `contents: read` permissions.
   - Cache pip and cartopy Natural Earth downloads if plot tests need
     coastline shapefiles (or ensure plot tests work offline with the
     synthetic fixture).
4. **Branch protection documentation**
   - Document (README and/or design.md) enabling a branch protection rule
     on `main` that requires the CI check to pass before merge (manual
     repository-settings step).
5. **Documentation updates**
   - Update `docs/design.md` (Testing + new CI section) and `README.md`
     (running tests, CI badge optional).
   - Update `docs/requirements.md` traceability (N1 ↔ Sprint 4) if
     appropriate.

## Acceptance Criteria

- CI workflow runs on PRs targeting `main` and pushes to `main`
- CI passes on a clean checkout without the 119 MB sample granule
- Both `pytest` and `mkdocs build --strict` are executed and gate the run
- Full local test suite (with the real sample file) still passes
- Branch protection setup is documented

## Testing Requirements

- New capability (synthetic fixture) is itself tested: reader functions,
  quality masking, bounds computation, plot smoke tests (Agg backend, PNG
  produced), and CLI smoke test all run against the synthetic file
- Real-file tests remain and run locally when `data/` contains the granule
- Run locally with `.venv/bin/pytest` from the project root

## Environment / Dependency Changes

- No new runtime dependencies expected (`netCDF4`/`h5py-via-netCDF4`
  already available for writing the fixture); if a direct `h5py` dependency
  is needed for fixture creation, add it to the `dev` extra in
  `pyproject.toml`

## Dependencies and Blockers

- Depends on Sprints 1-3 (package, tests, docs toolchain) — all complete
- Branch protection requires repository admin action (manual step)

## Documentation Updates

- `docs/design.md`: CI workflow description, testing-without-data strategy
- `README.md`: CI/testing notes, branch protection note
- Docstrings for any new helper code (NumPy style)

## Definition of Done

- `ci.yml` merged and green on a PR from a branch without local data
- Tests pass both with and without the real sample granule
- Docs updated (`design.md`, `README.md`)
- Branch protection rule documented (and enabled by the repo admin)
